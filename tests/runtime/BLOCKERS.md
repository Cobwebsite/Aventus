# Points à analyser pour les tests du runtime

- **Écriture par chemin avec intermédiaire primitif.** `setValueToObject('count.value', obj, x)` remplace un `count` falsy (`0`, `false` ou `null`) par un objet, mais laisse un `count` numérique truthy inchangé sans signaler d'échec. Le test `object-path.test.mjs` caractérise ce traitement dépendant de la vérité de la valeur ; décider si une valeur primitive doit provoquer une erreur ou être remplacée de façon cohérente.
- **Écriture avec chemin vide.** `getValueFromObject('', obj)` retourne `obj`, tandis que `setValueToObject('', obj, x)` écrit dans la propriété de clé vide de `obj`. Le test `object-path.test.mjs` vérifie cette asymétrie ; décider si le chemin vide doit être accepté en écriture.
- **Dates natives dans `compareObject`.** Deux instances JavaScript natives `Date` de timestamps différents sont considérées égales : la comparaison ne reconnaît que les classes calendrier du runtime et voit deux objets sans clés. Le test `compare-object.test.mjs` caractérise ce résultat ; décider si les dates natives appartiennent au contrat de comparaison.
- **Cycles dans `compareObject`.** Un même objet cyclique comparé à lui-même renvoie `true`, mais deux objets cycliques distincts de même structure entraînent un `RangeError` par récursion sans borne. Le test `compare-object.test.mjs` caractérise ce cas ; décider du résultat attendu pour les graphes cycliques.
- **Proxy `Watcher` dans `compareObject`.** Un proxy `Watcher` est considéré différent d'un objet ordinaire contenant les mêmes valeurs, avant et après modification du proxy. Le test `compare-object.test.mjs` vérifie ce résultat ; décider si la comparaison doit ignorer les métadonnées du proxy ou imposer une extraction préalable.
- **Entrées invalides de `Json`.** `Json.classToJson(null)` et `Json.classFromJson(obj, null)` lèvent une `TypeError` ; le second cas laisse l'objet cible inchangé. Le test `json.test.mjs` caractérise ces erreurs ; décider si l'API doit les conserver ou retourner un résultat contrôlé.
- **Conflits de clés dans `Json`.** `classToJson` laisse la dernière valeur écrite lorsqu'un renommage fait converger plusieurs clés. `classFromJson` privilégie la clé exacte, mais utilise sa variante capitalisée si la valeur exacte est `undefined`. Le test `json.test.mjs` vérifie ces règles ; décider si les collisions et la valeur `undefined` explicite doivent être traitées autrement.
- **Dates natives dans `Converter`.** Une instance JavaScript native `Date` est transformée en objet ordinaire vide, car le convertisseur ne reconnaît que les classes calendrier du runtime. Le test `converter.test.mjs` caractérise cette perte de timestamp ; décider si les dates natives doivent être préservées ou converties.
- **Schéma passé à `Converter.register`.** Le paramètre `schema` est stocké dans une map privée, mais aucun chemin de transformation ne lit cette map dans `base/src/tools/Converter.lib.avt`. Déterminer si le schéma enregistré doit valider ou guider la conversion avant d'écrire des assertions sur les schémas invalides.
- **Attentes en cours lors de `Mutex.dispose`.** `dispose()` vide la liste des attentes sans résoudre leurs promesses, puis libère le verrou pour les nouveaux appels. Le test `mutex.test.mjs` vérifie qu'une attente antérieure reste non résolue même après une nouvelle acquisition et libération. Décider si la destruction doit résoudre ou rejeter les attentes annulées.
- **Ancien sous-objet `Watcher` après remplacement.** Après `model.child = nouveau`, une édition via l'ancien proxy `child` émet encore une notification au chemin `child.count`, alors que l'extraction du modèle contient uniquement la nouvelle valeur. Le test `reactivity.test.mjs` caractérise cette notification résiduelle ; décider si le remplacement doit détacher les anciens proxys et leurs abonnements.
- **Ancien sous-objet `Watcher` après suppression.** Après `delete model.child`, modifier l'ancien proxy continue de notifier l'abonné racine avec le chemin `undefined.count`, alors que `child` n'existe plus dans le modèle extrait. Le test `reactivity.test.mjs` caractérise ce chemin invalide ; décider si le proxy doit être désabonné ou conserver une notification avec un chemin défini.
- **Référence partagée dans un modèle `Watcher`.** Si `left` et `right` référencent le même sous-objet, modifier `left.count` actualise aussi `right.count`, mais ne notifie que `left.count` ; modifier par `right` ne notifie que `right.count`. Après suppression de `left`, `right` continue de fonctionner. Le test `reactivity.test.mjs` caractérise ces chemins ; décider si tous les chemins qui pointent vers la même donnée doivent être notifiés.
- **Erreurs applicatives de `StorableRoute`.** Une réponse HTTP 422 contenant `{ errors: [...] }` produit désormais une erreur HTTP avec le statut 422, sans décoder les erreurs applicatives dans le résultat. Le test `storable-route.test.mjs` caractérise ce cas ; décider si le routeur doit aussi interpréter les erreurs applicatives ou laisser ce traitement au middleware ou à l'appelant.
- **Réponse DELETE 204 de `StorableRoute`.** Une suppression renvoyant 204 sans corps provoque une erreur de décodage JSON dans `Delete()`, bien que `queryVoid()` traite explicitement 204. Le test `storable-route.test.mjs` caractérise cette différence ; décider si `Delete()` doit utiliser une réponse vide.
- **Exception des hooks de `StateManager`.** Une exception synchrone de `onActivate` ou `onInactivate` fait retourner `false` à `setState()`, mais le nouvel état est déjà stocké comme actif. Le test `state-manager.test.mjs` vérifie ces deux cas et la reprise après échec d'activation. Décider si la transition doit être annulée ou si la valeur de retour doit refléter l'état effectivement atteint.
- **Changement de signal pendant un `Effect`.** Si le callback d'un effet modifie un signal qu'il vient de lire, l'effet ignore la notification pendant sa propre exécution et ne se relance pas pour cette nouvelle valeur. Le prochain changement externe le relance normalement. Le test `reactivity.test.mjs` caractérise ce résultat ; décider si un second passage doit être programmé après l'exécution courante.
- **Annulation dans `PressManager`.** `pointercancel` suit le même chemin que `pointerup` : après un `pointerdown` valide, il émet `onPress` et `onPressEnd` puis retire les listeners document. Le test `press-manager.test.mjs` caractérise ce comportement ; décider si une annulation doit éviter l'action de pression.
- **Branche conditionnelle de `TemplateInstance` à la destruction.** Le changement de condition détruit la branche précédente, mais `TemplateInstance.destructor()` ne détruit pas la branche encore active : seul l'ancrage racine est retiré dans le DOM simulé. Le test `template-bindings.test.mjs` caractérise cette différence ; décider comment suivre et nettoyer l'instance conditionnelle active.
- **Échec de lecture dans `HttpResponse`.** Après un premier `text()` rejeté, `bodyUsed` reste vrai et le second `text()` renvoie `undefined` sans réessayer. Le test `http-cache.test.mjs` caractérise ce résultat. Décider si l'échec doit rester mémorisé, être relancé, ou être rejoué.
- **Résultat falsy dans `ResultWithError`.** `run()` et `VoidWithError.extract()` ne propagent pas un résultat réussi égal à `0` (même condition pour `false` ou `''`), car ils testent sa vérité. Le test `error-result.test.mjs` caractérise ce cas. Décider si toute valeur définie doit être conservée.
- **Chargement CSS échoué dans `ResourceLoader`.** `loadInHead()` renvoie `false` au premier événement `error`, puis `true` au second appel pour la même URL sans recréer le lien. Le test `resource-loader.test.mjs` caractérise ce cache d'échec comme succès. Décider si un nouvel essai doit être possible ou si l'échec doit rester mémorisé comme échec.
- **`Enum` et `MergePrototype`.** Les fichiers `base/src/tools/Enum.lib.avt` et `MergePrototype.lib.avt` ne déclarent que des types TypeScript, sans fonction ou classe runtime exportée à tester. Leur validation relève d'un test de compilation de types si ces contrats doivent être couverts.
- **Comparaison des `Map`.** Deux `Map` de même taille mais avec des valeurs différentes sont considérées égales par `compareObject`. La boucle sur les clés utilise `for...in` sur un itérateur et ne parcourt aucun élément. Le test `compare-object.test.mjs` crée les deux maps dans le realm du runtime et caractérise ce résultat. Décider du contrat d'égalité des clés et valeurs.
- **Lectures concurrentes et formats de `HttpResponse`.** Une seconde lecture lancée pendant le premier `text()` obtient `undefined` ; après un `text()` terminé, `json()` renvoie la chaîne texte sans décodage. Le test `http-cache.test.mjs` caractérise ces deux cas. Décider si la promesse en cours doit être partagée et si les méthodes de lecture doivent refuser un format incompatible.
- **Borne `untilNode` d'`ElementExtension.findParent`.** Avec `leaf -> section -> root` et `untilNode = section`, `findParentByClass(leaf, 'root', section)` renvoie quand même `root`. La borne est comparée après le passage au parent suivant. Le test `element-extension.test.mjs` caractérise cette traversée ; décider si la recherche doit s'arrêter avant ou après la borne.
- **Ordre d'arrêt d'`Animation`.** Après `stop()`, la frame suivante appelle `stopped()` immédiatement puis exécute le callback `animate()` déjà programmé par `setTimeout`. Le test `animation.test.mjs` caractérise cet ordre. Décider si `stopped()` doit intervenir après la dernière animation ou si cette dernière doit être annulée.
- **Cible partagée de `ResizeObserver`.** Deux wrappers peuvent s'abonner à la même cible via l'observateur natif unique. Lorsque le premier se déconnecte, il appelle `unobserve` sur la cible native alors que le second reste abonné. Le test `resize-observer.test.mjs` caractérise cette perte de surveillance ; décider si la cible native doit rester observée jusqu'au dernier abonné.
- **Échec de `Style.load`.** Si le transport échoue, le `catch` absorbe l'erreur sans libérer `stylesheetsWaiting`. Un second chargement de la même paire nom/URL attend une promesse qui ne se résout pas et ne relance pas le transport. Le test `style.test.mjs` caractérise cet état ; décider du résultat d'échec et de la politique de nouvel essai.
